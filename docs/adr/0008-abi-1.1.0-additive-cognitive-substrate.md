# ADR 0008 — ABI 1.1.0: additive cognitive-substrate input (perception→memory loop closure)

- **Status**: Accepted
- **Date**: 2026-05-19
- **Deciders**: Daniel Penin (PCI steward) — explicit in-session authorization
- **Supersedes/affects**: PCI.2 (`docs/contracts/pci/02-abi-schema.md`), UTP-ABI-002

## Context

The Cognitive State ABI builder (`backend/src/kloel/abi/abi-builder.service.ts`,
UTP-ABI-002) emitted hardcoded empty `perception.recentSalientEvents`,
`memory.workingMemory`, `memory.episodicRefs`, `memory.consolidatedRefs`. This
is the "shadow mode inicial" explicitly described in PCI.2 §5.6. As a result the
cognitive organism never closed the perception→memory loop: PULSE stayed at
`INSUFFICIENT_EVIDENCE`, working memory stayed empty, no emergence possible.

PCI.2 is a frozen immutable contract (UTP-PCI-002, frozen 2026-05-13). Any
change requires steward authorization. PCI.2 §4 permits **additive optional**
changes as a `minor` `abiVersion` bump. PCI.2 §5.1 already mandates the builder
"lê estado atualizado de mind, brain, pulse, lineage, spine"; §5 mandates the
builder be PURE (same input → same output).

## Decision

Bump `ABI_VERSION` `1.0.0 → 1.1.0` (additive, PCI.2 §4 "Adição de campo opcional
novo → minor"). Add an **optional** `cognitiveSubstrate` field to the builder
INPUT (`AbiBuildInput`), not to the ABI payload schema. The payload fields
(`workingMemory`, `recentSalientEvents`, `episodicRefs`, `consolidatedRefs`)
were always present in the frozen schema — they are now *populated* instead of
hardcoded empty.

Purity is preserved: the builder remains a pure function of its input. The
impure reads (DB / perception substrate) live in the caller
(`BrainCapabilityExecutorService.buildCognitiveSubstrate`), which uses the
existing `MindPerceptionService` (autopilot events, messages, sales, orders) and
the pure `MemoryProjector` (commem) to project real workspace events into the
memory dimensions — 100% real data, zero hardcode, zero synthetic fill. When
`cognitiveSubstrate` is absent the builder falls back to the historical empty
defaults, so every existing caller is forward-compatible and unchanged.

Steward authorization: Daniel Penin selected "Bump aditivo abiVersion
1.0.0→1.1.0" in-session on 2026-05-19, explicitly authorizing the PCI doc +
CHECKSUMS amendment recorded by this ADR.

## Consequences

- PCI.2 doc version `1.0.0 → 1.1.0`; CHECKSUMS.txt regenerated for
  `02-abi-schema.md`; manifest version `1.0.0 → 1.1.0`.
- ABI specs (`abi-stability`, `abi-validator`, `abi-builder.service`): 33/33
  pass — additive change is non-breaking and forward-compatible.
- Closes phase 2/4 of the cognitive-organism program (perception→memory).
- **Rollback**: revert the builder edit — the `?? []` fallback restores exact
  1.0.0 behavior; no data migration, no payload-shape change.

## Alternatives considered

- ADR-first then implement (more traceable, slower) — steward chose direct
  additive bump.
- Touch builder to read state directly (breaks PURE invariant) — rejected;
  impurity kept in the caller per PCI.2 §5.
