## What NOT to do

- **DON'T render the dead edit/trash buttons** — delete them (already
  covered: removing the entire Dominios component body eliminates them).
- **DON'T fake domain data** — no `DomainItem[]` with placeholder entries.
- **DON'T fake hosting metrics** — no hardcoded CPU/Mem/Storage/Bandwidth.
- **DON'T fake security events** — no hardcoded "Atividade Recente" log.
- **DON'T fake SSL certificates** — no hardcoded domain cert list.
- **DON'T add backend endpoints that return `[]`** — the CLAUDE.md
  contract is clear: empty arrays from Prisma are fine for features that
  _exist_ and are wired. These features do not exist yet; adding a
  `GET /kloel/site/domains` that returns `[]` would create a fake API
  surface that implies readiness.
- **DON'T create Prisma models for these features** — that is a Wave 5+
  product decision, not a stub-route cleanup.---

## Risk assessment

### What breaks if we ship this?

**Nothing user-facing breaks.** These tabs currently show fake data that
users cannot interact with (dead buttons, non-persistent toggles).
Replacing them with honest-state messages is a strict UX improvement:
users go from "this looks broken" to "this is coming soon."

### What depends on these components?

- `SitesView.tsx` — imports and renders all four components via tab
  switching. No props are passed to Dominios, Hospedagem, Apps, or
  Protecao — they are self-contained. The import list shrinks.
- `VisaoGeral.tsx` (Visao Geral tab) — has "Acoes Rapidas" buttons that
  call `switchTab('dominios')`, `switchTab('apps')`, `switchTab('protecao')`.
  These still work — they just navigate to tabs that now show honest
  messages instead of fake data.
- `SitesView.tabs.ts` — tab definitions (unchanged; tabs remain in nav).
- Route pages — 4 thin shell pages under `frontend/src/app/(main)/sites/`
  (unchanged; they still render `SitesView` with the correct `defaultTab`).

### Workspace isolation

- Not applicable — no data is read or written. These are purely
  presentational changes.---

## Implementation notes

### Consistency with existing honest-state patterns

The repo already has `EmptyStates.tsx` with a `ContextualEmptyState`
component and `EMPTY_STATE_CONFIGS`. For these four tabs, however, the
simplest approach is inline honest-state within each component rather
than adding entries to EMPTY_STATE_CONFIGS, because:

1. These tabs already use the Sites module's inline styling system
   (`Card`, `SectionLabel`, `SORA`, `MONO`, `EMBER` design tokens).
2. Adding to EMPTY_STATE_CONFIGS would couple the Sites module to the
   generic empty-state system, when these are temporary honest states
   that will be replaced with real UIs when the features ship.

The recommended approach: a simple `Card` with icon, title, description,
and optional CTA — matching the visual language already used by these
components.

### PR sizing

These are four small, independent frontend-only changes. One PR per tab
is safe, but a single PR covering all four is also fine (total diff ~200
lines removed, ~80 lines added).

### Test impact

- No existing tests for Dominios, Hospedagem, Apps, or Protecao were
  found in the test directory.
- `VisaoGeral` has `switchTab` calls to these tabs — those remain
  functional.
- Zero test regression risk.---

## Migration plan

### PR 1 (all four tabs, single PR): Delete fake data + add honest-state UI

1. **Dominios.tsx**: Replace component body with honest-state card.
   Remove `DomainItem` type, `useState` hooks, domain table, add-domain
   form, fake DNS config, and dead edit/trash buttons.
2. **Hospedagem.tsx**: Replace component body with honest-state card.
   Remove hardcoded stat cards, ProgressBar usage, server info grid,
   and fake uptime chart.
3. **Apps.tsx**: Replace component body with honest-state card.
   Remove `useState` hooks for `installedApps`/`availableApps`,
   the two empty-state sections, and the unreachable "Instalar" button.
4. **Protecao.tsx**: Replace component body with honest-state card.
   Remove `useState` hooks for toggle switches, fake security scorecard,
   hardcoded SSL cert list, and fake activity log.

No backend changes. No Prisma changes. No route changes.

### PR 2 (future, separate ADRs): Replace honest-state with real wiring

When the product team decides to ship one of these features, the
corresponding honest-state component is replaced with real UI that calls
the then-existing backend endpoints and Prisma models. Each feature
requires its own ADR because it involves new infrastructure integration
(Cloudflare API, Railway/Vercel deployment API, app marketplace
architecture, WAF/security configuration).---
